# Cursor AI 对话与分析开发规则

> **适用范围**: 所有涉及 AI 对话、分析、生成的代码
> **强制级别**: 必须遵守

## 对话上下文记忆

### 必须维护的上下文
每次对话调用必须传递：
- `session_id`: 当前会话 ID（不能每次都新建）
- `user_goal`: 用户当前核心诉求
- `user_exclusions`: 用户明确排除的事项（如"只处理劳动报酬，排除股东纠纷"）
- `conversation_history`: 最近对话历史

### 上下文传递示例
```python
# ✅ 正确：传递完整上下文
@router.post("/chat")
def chat(request: ChatRequest):
    # 从上下文存储中获取会话上下文
    ctx = get_conversation_context(request.session_id)
    
    # 将用户诉求和排除范围加入提示词
    prompt = f"""
    用户诉求：{ctx.user_goal}
    用户明确排除：{ctx.user_exclusions}
    
    用户当前问题：{request.message}
    
    相关证据：{ctx.relevant_evidence}
    """
    return llm_service.chat(prompt)

# ❌ 错误：不维护上下文
@router.post("/chat")
def chat(request: ChatRequest):
    return llm_service.chat(f"用户问：{request.message}")
```

## Prompt 设计规则

### 必须包含的模块（按顺序）
1. 【角色定义】- AI 扮演的专业身份
2. 【核心原则】- 必须遵守的原则（至少包含：无溯源不输出法条、不确定必须表达、不讨好用户）
3. 【禁止行为】- 绝对不能做的事
4. 【输入数据】- 用户提供的案件信息
5. 【任务要求】- 用户的要求（含诉求和排除范围）
6. 【输出格式】- 期望的输出结构

### 法律引用强制规则
```
✅ 正确引用格式：
"依据《民法典》第五百七十七条：当事人一方不履行合同义务或者履行合同义务不符合约定的，应当承担继续履行、采取补救措施或者赔偿损失等违约责任。"

❌ 禁止格式：
"根据合同法..."（未指明具体条文）
"按照一般法律原则..."（未指明具体法条）
```

### 证据分析强制规则
```
⚠️ 分析必须基于【完整证据原文】，禁止以下行为：
1. 仅凭证据名称（如"投资协议"）推测内容
2. 仅分析前几页或摘要，对具体条款全文视而不见
3. 在证据原文未提供某条款时假设该条款存在
4. 用"通常"、"一般"等词汇掩盖未看到原文的事实

✅ 正确做法：
- 仔细阅读证据全文的每一个条款
- 在证据原文未提供某条款时，明确标注"原文未提及此条款"
```

## 禁止性规定（高压红线）

| 禁止行为 | 替代方案 |
|---------|---------|
| 编造不存在的法条或司法解释 | 明确标注"该法条不存在" |
| 虚构不存在的案例 | 返回"未找到相关案例" |
| 捏造证据内容 | 返回"原文未提及此内容" |
| 为讨好用户夸大胜诉概率 | 给出客观评估，标注不确定性 |
| 用户说"只处理X"，AI却引入Y | 严格按用户诉求范围回答 |

## 文书生成规则

### 必须遵循的流程
1. **理解诉求**：用户要什么？排除什么？
2. **筛选证据**：只引用与诉求相关的证据
3. **起草文书**：只写诉求范围内的内容

### 排除性描述处理
如果用户说"不包括XXX"、"只申请YYY"：
- 文书正文中绝对不能出现被排除的内容
- 证据部分不引用被排除的证据
- 在提示词中明确传递排除范围

## 不确定性表达规范

| 确定性程度 | 表达方式 |
|-----------|---------|
| 高（>90%） | "依据《X法》第X条..." |
| 中（60-90%） | "依据《X法》第X条，但各地法院存在差异..." |
| 低（<60%） | "目前缺乏明确法律依据，建议咨询专业律师" |
| 完全不确定 | "我无法核实您提到的具体情况" |
