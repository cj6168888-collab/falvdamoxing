# 法律 AI 辅助系统律师工作流升级路线图

> 目标：把现有功能从“AI 功能集合”升级为“律师真实办案工作台”。本文用于产品规划、提示词把关、页面命名和后续验收。

## 一、总体判断

当前项目不是缺功能，而是功能需要按律师办案顺序重新组织。现有模块已经覆盖案件、证据、智能问答、文书、庭审、上诉、执行、费用和提醒，基础盘很完整。

下一阶段最重要的升级不是继续堆 AI 能力，而是让每个输出都回答三个问题：

1. 这个结论依据哪些事实和证据？
2. 这个建议对应哪一个法律关系、请求权基础或程序节点？
3. 哪些内容必须人工核验后才能对外使用？

## 二、律师真实工作流

| 阶段 | 律师真实任务 | 系统已有入口 | 当前问题 | 升级方向 |
|---|---|---|---|---|
| 1. 接案评估 | 识别案由、主体、管辖、时效、利益冲突、诉讼成本 | 案件管理、法律 AI 助手、费用管理 | 缺少“接案清单”和“不能接/慎接风险” | 新增接案评估卡：主体、时效、管辖、证据基础、成本收益、风险等级 |
| 2. 委托确认 | 明确客户目标、代理范围、授权材料、收费方式 | 案件管理、当事人、费用管理 | 功能分散，未形成委托前置校验 | 增加委托材料清单和授权风险提示 |
| 3. 事实整理 | 梳理时间线、关键事实、争议焦点 | 时间线、智能对话、案件画像 | AI 结论和证据原文有时未强绑定 | 输出统一为“事实点 -> 证据 -> 待核验” |
| 4. 请求权基础 | 判断合同/侵权/公司/劳动等法律关系，拆分诉请 | 资深分析、增强分析、报告 | 这是律师最核心的判断，但目前不是独立主线 | 增加“请求权基础矩阵” |
| 5. 证据审查 | 三性、证明目的、证明力、缺口、补强 | 证据管理、证据图谱、补证引导 | 方向很对，但需要更标准的字段化输出 | 每份证据固定输出来源、原件状态、证明目的、三性风险、补强建议 |
| 6. 策略评估 | 诉讼/调解/保全/反诉/抗辩路径 | 诉讼风险分析、对抗分析、费用管理 | 旧表达偏“攻防刺激”和“胜诉概率” | 全部改为风险、条件、收益、失败后果 |
| 7. 文书起草 | 起诉状、答辩状、代理词、律师函、证据目录 | 文书草稿、报告、函件 | 必须强调草稿状态和核验清单 | 导出前强制核验当事人、金额、事实、证据、法条、管辖、签章 |
| 8. 庭前准备 | 庭审提纲、质证意见、发问提纲、证据交换 | 庭审辅助、对抗分析 | 应避免“实时指挥”，更像庭前工作底稿 | 每个问题标注发问目的、关联证据、风险提示 |
| 9. 庭后/上诉 | 庭审记录复盘、判决分析、上诉理由 | 庭审、上诉跟踪 | 需要把判决要点和上诉理由结构化 | 增加“裁判理由拆解 -> 可上诉点 -> 新证据/程序问题” |
| 10. 执行 | 财产线索、执行申请、查控、和解 | 执行跟踪 | 方向正确，但可与证据/费用联动更深 | 财产线索证据化、执行成本和回款概率分层 |

## 三、功能需要程度排序

| 功能 | 律师需要程度 | 判断 |
|---|---:|---|
| 证据三性分析 + 证明目的 | 5/5 | 最贴近律师日常，且能显著减少低价值沟通 |
| 请求权基础矩阵 | 5/5 | 这是法律分析的骨架，建议作为 P0 |
| 时间线 + 事实点证据映射 | 5/5 | 没有事实结构，后续文书和庭审都会漂 |
| 文书草稿 + 导出前核验 | 5/5 | 高频刚需，但必须保持草稿定位 |
| 补证清单 | 5/5 | 普通用户和律师都需要，商业价值高 |
| 庭审发问/质证提纲 | 4/5 | 对诉讼律师有价值，需建立证据锚点 |
| 诉讼风险评估 | 4/5 | 有价值，但必须避免承诺结果 |
| 对抗/沙盘推演 | 3/5 | 适合律师版，不建议普通用户默认突出 |
| 类案/法条检索 | 4/5 | 价值高，但要严格区分官方来源和普通裁判文书 |
| 费用与成本收益 | 3/5 | 对客户沟通有用，可作为接案评估辅助 |

## 四、下一批 P0 升级

### P0-1 请求权基础矩阵

新增一个标准输出结构：

```json
{
  "claim_basis": "合同违约/侵权/公司损害责任等",
  "legal_elements": [],
  "facts_to_prove": [],
  "supporting_evidence": [],
  "missing_evidence": [],
  "opponent_defenses": [],
  "risk_level": "high|medium|low",
  "requires_human_review": true
}
```

验收标准：

- 每个诉请必须对应一个请求权基础。
- 每个构成要件必须对应事实和证据。
- 不能只输出自然语言结论。
- 当前前端已在资深律师分析结果页接入“请求权基础矩阵”，把后端要件核对结果结构化展示为请求权基础、构成要件、事实/证明对象、支持证据、缺口证据、对方可能抗辩/常见问题、风险等级和人工复核状态。后续可继续把诉请拆分、法律依据条款和金额计算升级为独立后端模型。

### P0-2 事实-证据-结论三栏

所有 AI 分析页面都应固定分栏：

| 栏目 | 内容 |
|---|---|
| 已有事实 | 用户提供或证据原文可确认的事实 |
| AI 推断 | 根据事实进行的法律分析或策略推演 |
| 待核验事项 | 缺证据、缺法条、需人工确认的内容 |

验收标准：

- AI 不得把推断写成事实。
- 没有证据编号的事实不得进入“已有事实”。
- 待核验事项必须可以转成任务清单。
- 当前前端已在资深律师分析结果页接入“事实-证据-结论三栏”：已有事实仅展示后端 `evidence_mapping` 中带证据编号/证据类型/信度的事实；AI 推断独立展示争议焦点、要件覆盖判断和下一步建议；待核验事项独立展示不确定事项、要件缺口、证据缺口、程序问题和薄弱论证，并同步生成“待核验任务清单”，按补证、程序核验、事实核验、论证补强分类展示优先级和下一步动作。

### P0-3 文书导出前核验清单

导出文书前必须弹出核验清单：

- 当事人名称、身份证号/统一社会信用代码。
- 法院、管辖、案由。
- 诉讼请求、金额、利息计算方式。
- 事实理由是否均有证据支撑。
- 法条引用是否为现行有效版本。
- 证据目录编号是否对应。
- 日期、签名、盖章、授权材料。

验收标准：

- 用户未确认清单时，导出文件应标注“AI 草稿，待人工核验”。
- 对外发送类文书必须增加授权和后果提示。
- 当前前端已在文书草稿、历史文书预览、历史文书列表的 Word/PDF/Markdown/证据册导出前接入核验弹窗；清单已拆分为当事人身份、法院/管辖/案由、诉讼请求/金额/利息、事实证据对应、法条现行有效性、证据目录编号、日期签章版本、授权材料和对外发送后果 8 项；后端强制记录并校验完整勾选项，同时保存核验人、租户、案件、文书、导出动作和导出格式；文书预览和下载页已展示导出核验记录。

### P0-4 证据详情固定字段

每份证据详情页固定展示：

```json
{
  "source": "",
  "formed_at": "",
  "original_status": "original|copy|screenshot|unknown",
  "facts_supported": [],
  "proof_purpose": "",
  "authenticity_risk": "",
  "legality_risk": "",
  "relevance_risk": "",
  "strengthening_actions": [],
  "requires_human_review": true
}
```

验收标准：

- 电子证据必须提示原始载体、导出方式、账号主体、时间戳、上下文完整性。
- 证明目的不能为空。
- 当前前端已在证据详情页接入固定审查字段：材料来源、形成/取得时间、原件状态、证明目的、真实性风险、合法性风险、关联性风险、内容可读性和关联事实；电子证据会提示原始载体、导出方式、账号主体、时间戳、上下文完整性和存证/公证记录。当前已增加人工复核表单，可保存材料来源、形成/取得时间、原件状态、证明目的、三性风险、补强动作和复核备注；后端会记录最新复核人、复核时间并在证据列表/详情中读回展示，且“证明目的”为空时拒绝保存。文书生成和大型证据目录已优先使用人工复核的证明目的，再回退到证明事实、AI 摘要或原文摘录；证据目录和通用文书证据段也会带出人工复核的真实性/合法性/关联性风险与补强动作，避免只输出证明目的而丢失审查结论。

## 五、律师/普通用户分层

### 普通用户默认模式

适合表达：

- 你还缺哪些材料。
- 哪些事实目前证据不足。
- 这件事有哪些风险。
- 咨询律师前应准备什么。

避免表达：

- 直接给诉讼结论。
- 强烈鼓励起诉。
- 使用“必胜”“对方违法无疑”“法院一定支持”。

### 律师工作模式

可显示专业字段：

- 请求权基础。
- 构成要件。
- 举证责任。
- 证据三性。
- 质证意见。
- 程序抗辩。
- 保全/反诉/管辖策略。

限制：

- 仍需保留证据锚点、法条来源、人工核验状态。
- 不应把 AI 输出称为正式法律意见。

## 六、建议的近期开发顺序

1. 先做“请求权基础矩阵”和“事实-证据-结论三栏”，这是法律逻辑骨架。
2. 再做“文书导出前核验清单”，这是合规和产品信任底线。
3. 然后做“证据详情固定字段”，让证据模块真正变成律师可用的工作底稿。
4. 最后再优化对抗分析、庭审辅助和类案检索，不急着继续堆大模型表演型功能。

## 七、命名规范

| 不建议 | 建议 |
|---|---|
| AI 律师 | 法律 AI 助手 |
| 文书生成 | 文书草稿 |
| 出庭抗辩 | 庭审辅助 |
| 胜诉概率 | 裁判支持度参考/诉讼风险评估 |
| 攻击点 | 质证重点/争议风险点/核心质疑点 |
| 一键生成 | 生成草稿/生成工作底稿 |
| 精准预测 | 风险提示/倾向参考 |
