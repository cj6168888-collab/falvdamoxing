# 法律 AI 辅助系统产品把关清单

> 适用对象：本项目的证据管理、对抗性分析、文书生成、庭审/出庭辅助、智能问答、法律检索与报告模块。
>
> 核心定位：本系统是法律工作辅助系统，用于整理事实、提取证据、生成工作底稿、提示风险、辅助检索；不替代律师执业判断，不承诺诉讼结果。

## 一、当前项目判断

项目方向总体是对的：已经围绕案件、证据、文书、庭审、期限、对抗分析和法律知识库展开，这些都贴近律师真实工作流。

但当前最大风险不在功能数量，而在三个方面：

1. 产品话术有时偏“替用户下法律结论”，例如“胜诉概率”“一键生成”“深度创作文书”“攻击点”等表达，容易越过辅助工具边界。
2. AI 输出还需要更强的证据锚定机制，必须把“事实、证据、法律依据、待核验项、人工确认状态”拆开。
3. 普通用户版和律师版应当分层。律师版可使用“请求权基础、举证责任、质证意见、证明目的”；普通用户版应使用“事实依据、证据说明、风险提示、下一步准备”。

## 二、监管和行业边界

本项目至少应按以下规则设计产品边界：

1. 生成式 AI 服务应坚持发展和安全并重、依法治理、分类分级监管，并避免生成虚假违法信息。参考国家网信办等部门《生成式人工智能服务管理暂行办法》：https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm
2. 案件材料通常包含身份证、手机号、住址、银行流水、聊天记录、合同、工资社保、医疗或家庭信息，应按个人信息和敏感个人信息处理。参考《个人信息保护法》：https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm
3. 律师事务所和律师依法开展业务并承担责任，产品文案不能让用户误以为系统本身在提供律师执业服务。参考司法部《律师事务所管理办法》：https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/200902/t20090209_144629.html
4. 律师行业强调依法、诚信、尽责执业，系统输出应避免夸大、煽动、违规炒作案件或承诺结果。参考全国律协相关行业规则入口：https://www.acla.org.cn/

## 三、产品定位红线

必须避免：

1. 不得宣称“AI 律师”“替代律师”“自动打官司”“保证胜诉”。
2. 不得输出“必然胜诉”“一定违法”“法院一定支持”等确定性结论。
3. 不得把未核验材料写成既定事实。
4. 不得引用未核验法条、案例、案号、指导案例。
5. 不得把用户输入、AI 推断、证据原文混在一个结论里。
6. 不得默认向普通用户提供“正式法律意见书”语义的输出。

建议统一产品定位文案：

> 本系统生成内容为法律工作辅助材料，仅供事实整理、证据分析、风险提示和文书初稿参考。所有法律判断、诉讼策略、文书提交和对外发送，均需由具备相应资格的专业人士或使用者结合完整材料核验确认。

## 五、AI 输出标准结构

所有法律分析类输出建议固定为以下结构：

1. 事实摘要：仅基于用户输入和已上传材料，明确材料来源。
2. 争议焦点：列出双方可能争议的问题，避免直接下结论。
3. 法律关系或请求权基础：标明合同、侵权、公司治理、劳动、婚姻家事等关系。
4. 证据映射：事实点 -> 对应证据 -> 证明目的 -> 证明力 -> 缺口。
5. 法律依据：列出法条名称、条号、引用内容、现行有效状态。
6. 对方可能抗辩：主体、时效、履行、金额、因果关系、证据三性等。
7. 风险等级：高/中/低，并解释理由，不使用“胜诉保证”。
8. 待核验事项：所有没有证据支撑或来源不明的内容必须列入。
9. 下一步工作：补证、核验、文书修改、律师确认、提交节点。
10. 人工确认状态：未确认 / 已核验 / 已采用 / 已排除。

推荐给后端返回增加通用字段：

```json
{
  "content_type": "legal_work_draft",
  "confidence_level": "low|medium|high",
  "is_legal_advice": false,
  "requires_human_review": true,
  "source_materials": [],
  "legal_citations": [],
  "evidence_links": [],
  "assumptions": [],
  "unverified_items": [],
  "risk_warnings": [],
  "review_status": "pending"
}
```

## 六、模块级把关

### 1. 证据管理

已有优势：

- 已有证据上传、证据图谱、证据引导、证据缺口、三性分析等方向。
- `app/services/evidence_three_natures.py` 已经围绕真实性、合法性、关联性建模，这是非常贴近律师工作的模块。

建议升级：

1. 把“可信度评分”改为“证据风险参考”或“证明力参考”，避免让用户误解为司法认定。
2. 每份证据必须有：来源、形成时间、原件状态、证明目的、关联事实、三性风险、补强建议。
3. 电子证据单独标注：原始载体、导出方式、聊天上下文、账号主体、时间戳、公证/存证状态。
4. 证据分析不能只给自然语言结论，要输出表格化字段。

建议证据字段：

```json
{
  "evidence_name": "",
  "source_party": "",
  "formed_at": "",
  "original_status": "original|copy|screenshot|unknown",
  "proving_purpose": "",
  "linked_fact_ids": [],
  "authenticity_risk": "low|medium|high|unknown",
  "legality_risk": "low|medium|high|unknown",
  "relevance_risk": "low|medium|high|unknown",
  "opponent_challenge_points": [],
  "reinforcement_suggestions": [],
  "review_status": "pending"
}
```

### 2. 对抗性分析

已有优势：

- 模块覆盖对方抗辩、证据攻防、案件走向、行动方案，方向正确。

高风险点：

- `app/api/adversarial.py` 中存在“胜诉概率”字段和大量强诉讼策略语气。
- “攻击点”类词汇对普通用户偏刺激，建议替换为“质证重点”“反驳方向”“争议风险点”。

建议升级：

1. 把“胜诉概率”统一改为“裁判支持度参考”或“诉讼风险等级”。
2. 对抗分析不要直接输出单一路径，应输出“我方主张、对方抗辩、法院可能关注、补证动作”四列表。
3. 对每个策略加风险：收益、前提条件、证据要求、失败后果。
4. 对普通用户默认显示“风险提示版”，律师用户可打开“攻防推演版”。

推荐输出结构：

```json
{
  "claim_or_issue": "",
  "our_position": "",
  "opponent_possible_defense": "",
  "court_likely_focus": "",
  "supporting_evidence": [],
  "missing_evidence": [],
  "risk_level": "low|medium|high",
  "recommended_next_step": "",
  "unverified_assumptions": []
}
```

### 3. 文书生成

已有优势：

- 已有起诉状、答辩状、律师函、代理词等入口。

高风险点：

- 前端存在“一键生成”“深度创作文书”等表达，建议降级为“生成草稿”“起草初稿”。
- 文书生成必须强制草稿状态，不应默认成为可直接提交文件。

建议升级：

1. 所有生成文书标题、水印、元数据都标注“AI 草稿，待人工核验”。
2. 导出前增加确认清单：当事人信息、诉讼请求、事实理由、证据目录、法院/管辖、金额、日期、签名盖章。
3. 文书中的每个核心事实最好能回链到证据编号。
4. 对外发送类文书，如律师函、催告函，必须提醒用户核验身份、授权和发送后果。

文书导出前确认清单：

- 当事人名称、身份证号/统一社会信用代码是否准确。
- 管辖法院或收件主体是否准确。
- 诉讼请求金额和计算方式是否可核验。
- 事实理由是否均有证据支撑。
- 引用法条是否现行有效。
- 是否存在未经授权披露的个人信息或商业秘密。
- 是否由律师或使用者最终确认。

### 4. 出庭/庭审辅助

已有优势：

- 已有发问、质证、庭审模板、实时分析等方向。

高风险点：

- 庭审场景不能制造“实时操控律师”的感觉，尤其要避免诱导违法发问、虚假陈述或扰乱庭审秩序。

建议升级：

1. “攻击点”改为“质证重点”或“发问目的”。
2. 每个庭审问题必须标注：问题类型、发问目的、关联证据、预期事实、风险提示。
3. 增加庭审纪律提示：不得虚假陈述，不得伪造证据，不得诱导证人作虚假证言。
4. 实时分析结果仅作为庭后整理或提醒，不应称为“庭审指令”。

推荐发问结构：

```json
{
  "question": "",
  "question_type": "open|closed|clarifying|impeachment",
  "purpose": "",
  "linked_evidence": [],
  "expected_fact": "",
  "risk_note": "",
  "review_status": "pending"
}
```

## 七、普通用户版和律师版分层

### 普通用户版

使用目标：帮助用户整理材料、理解风险、准备咨询律师。

允许表达：

- “你还需要准备哪些材料”
- “这份材料可能能说明什么”
- “有哪些风险需要向律师确认”
- “下一步建议核验”

避免表达：

- “你一定能赢”
- “法院会支持”
- “直接这样起诉”
- “对方违法无疑”

### 律师版

使用目标：提升律师或法律工作者的工作底稿效率。

允许表达：

- 请求权基础
- 举证责任
- 证明目的
- 证据三性
- 质证意见
- 备位请求
- 类案裁判倾向

但仍要保留：

- 来源引用
- 待核验标签
- 人工确认状态
- 法条有效性提示

## 八、项目当前优先修改清单

### P0：必须先改

1. 全局增加法律免责声明和“AI 草稿/待核验”状态。
2. 替换“胜诉概率”为“裁判支持度参考/诉讼风险评估”。
3. 替换“一键生成文书”为“生成文书草稿”。
4. 对所有法条、案例、案号输出增加来源和核验状态。
5. 给证据、对抗分析、文书生成增加 `requires_human_review=true`。

### P1：短期升级

1. 对抗分析改为四列表：我方主张、对方抗辩、法院关注、补证动作。
2. 文书生成增加导出前确认清单。
3. 证据详情页增加“三性风险 + 证明目的 + 补强建议”固定区块。
4. 智能问答输出增加“事实依据/推断/待核验”分栏。
5. 增加普通用户版/律师版文案开关。

### P2：中期升级

1. 建立法律术语词典和禁用词扫描。
2. 建立提示词审计测试集，覆盖常见高风险问题。
3. 建立文书模板合规测试，检查是否缺少草稿标识、核验清单、证据引用。
4. 接入法条版本库或至少建立法条引用核验流程。
5. 建立案例引用可信度等级：官方指导案例、最高法公报案例、普通公开裁判文书、用户上传材料。

## 九、推荐统一页面提示

### 分析结果页

> 以下内容由 AI 根据当前材料生成，仅供案件事实整理和风险识别参考。AI 可能遗漏事实、误判法律关系或引用过期依据。请结合完整证据、现行法律法规和专业人士意见进行核验。

### 文书生成页

> 生成结果为文书草稿，不等同于正式法律文书。提交、发送或对外使用前，请逐项核验当事人信息、事实依据、诉讼请求、证据目录、法条引用、金额计算和签名盖章事项。

### 证据分析页

> 证据分析仅为证明力和风险参考，不能替代法院对证据真实性、合法性、关联性的最终认定。

### 对抗分析页

> 对抗分析用于模拟可能争议焦点和抗辩路径，不构成诉讼结果预测或胜诉承诺。

## 十、功能是否为律师需要

| 功能 | 律师需要程度 | 备注 |
| --- | --- | --- |
| 时间线整理 | 高 | 律师常用，建议支持证据回链 |
| 证据目录 | 高 | 必须包含证明目的和页码/编号 |
| 证据三性分析 | 高 | 非常有价值，但必须标注待核验 |
| 文书草稿 | 高 | 要强调草稿和人工确认 |
| 对方抗辩推演 | 高 | 律师会用，但要避免承诺结果 |
| 庭审发问提纲 | 高 | 要标注发问目的和风险 |
| 胜诉概率 | 中低且高风险 | 建议改为风险等级或支持度参考 |
| 智能聊天 | 中 | 应成为入口，不应成为核心交付 |
| 法条检索 | 高 | 必须保证来源和时效 |
| 类案检索 | 高 | 必须区分指导案例、参考案例、普通裁判 |
| 自动策略推荐 | 中高 | 必须给前提和失败风险 |

## 十一、实施建议

第一阶段先做低成本、高收益的“语言和结构护栏”：

1. 新增统一免责声明组件。
2. 替换高风险词。
3. 文书导出前增加确认弹窗。
4. 后端 AI 输出统一包一层 `review_status`、`unverified_items`、`source_materials`。
5. 给对抗分析和证据分析页面增加“待核验事项”区块。

第二阶段再做“律师工作流增强”：

1. 证据链映射表。
2. 请求权基础-事实-证据-法条四联表。
3. 文书段落到证据编号的引用回链。
4. 法条和案例引用核验。
5. 律师版/普通用户版双模式。

第三阶段做“合规和质量自动化”：

1. 禁用词扫描。
2. 幻觉引用检测。
3. 文书草稿审查测试。
4. 个人信息脱敏检查。
5. AI 输出审计日志。
