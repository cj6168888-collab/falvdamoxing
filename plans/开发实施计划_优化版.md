# 法律案件追踪系统 — 优化后的开发实施计划

> **基于 v3.0 计划文档的模块化开发调整方案**
> **核心原则：底层优先、模块独立、迭代交付、风险前置**

---

## 📊 调整前后对比

| 维度 | 原计划（14 天） | 新计划（6 周） | 改进点 |
|------|---------------|---------------|--------|
| 开发模式 | 按页面推进 | 按模块层级推进 | 依赖清晰，并行开发 |
| 迭代策略 | 一次性交付 | 3 个 MVP 迭代 | 早期可用，持续反馈 |
| 测试策略 | 最后 1 天 | 每模块即时测试 | Bug 早发现早修复 |
| 风险管控 | 无技术预研 | 第 0 周技术预研 | 高风险技术提前验证 |
| 团队适配 | 假设单人开发 | 支持 1-3 人并行 | 模块解耦，分工明确 |

## 🏗️ 模块化层级架构

```
层级 0：基础设施层（Infrastructure）
├── 项目脚手架 + ESLint/Prettier/TypeScript 配置
├── 设计系统（Design Tokens、Tailwind 配置、深色模式）
├── 路由框架 + App Shell 布局
└── 状态管理基础（Zustand stores、TanStack Query 配置）

层级 1：通用组件层（Shared Components）
├── UI 基础组件（Button、Input、Card、Dialog 等 35+）
├── 通用业务组件（CaseCard、StatusBadge、EmptyState 等）
├── 布局组件（Resizable Panel、Panel Layout）
└── 工具函数（日期、格式化、导出、打印）

层级 2：数据层（Data Layer）
├── API 客户端（Axios 拦截器、错误处理、重试机制）
├── TypeScript 类型定义（22 个类型文件）
├── 自定义 Hooks（useCase、useEvidence 等）
└── Mock 数据 + MSW 服务

层级 3：核心业务模块（Core Modules）
├── 案件管理（列表、新建、详情框架）
├── 当事人管理
├── 证据管理 V2
├── 文书生成
└── 对话 V2

层级 4：高级业务模块（Advanced Modules）
├── 对抗性分析
├── 时间把控（含函件管理）
├── 出庭抗辩（含语音功能）
├── 进度追踪
├── 执行跟踪
├── 上诉追踪
├── 报告中心
├── 提醒中心
├── 资深律师分析
├── 案件画像
├── 证据引导
└── 会议谈判（含录音功能）

层级 5：集成与优化（Integration & Polish）
├── 模块间联动集成
├── 导出功能
├── 响应式适配
├── 性能优化
├── 无障碍 (a11y)
├── 键盘快捷键
└── 完整测试 + Bug 修复
```

## 📅 6 周迭代计划

### 第 0 周：技术预研 + 基础设施（5 天）

**目标：** 验证高风险技术，搭建开发基础

| 天 | 任务 | 交付物 | 负责人 |
|----|------|--------|--------|
| D1 | 项目脚手架搭建 + ESLint/Prettier 配置 | 可运行的空项目 | 前端 |
| D2 | 设计系统搭建（Tailwind、CSS 变量、深色模式） | 设计 Token 文档 | 前端 |
| D3 | **技术预研：Web Speech API 语音识别** | 语音识别 Demo | 前端 |
| D4 | **技术预研：MediaRecorder 录音 + TTS 语音合成** | 录音+TTS Demo | 前端 |
| D5 | **技术预研：Resizable Panel 布局 + React Flow** | 布局+图谱 Demo | 前端 |

**预研验证清单：**
- [ ] Web Speech API 中文识别准确率 ≥ 90%
- [ ] MediaRecorder 录音文件可正常保存和播放
- [ ] TTS 语音合成自然度可接受
- [ ] Resizable Panel 拖拽性能流畅（60fps）
- [ ] React Flow 100 节点渲染性能可接受

## 🔀 并行开发策略（2-3 人团队）

### 角色分工

| 角色 | 职责 | 负责模块 |
|------|------|---------|
| **前端 A（主程）** | 架构设计、核心组件、复杂模块 | 基础设施、布局系统、出庭抗辩、语音功能 |


## ⚠️ 关键风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 语音识别准确率低 | 中 | 高 | 第 0 周预研验证，准备降级方案（手动输入） |
| Resizable Panel 性能问题 | 低 | 中 | 第 0 周预研验证，使用成熟库（react-resizable-panels） |
| API 接口变更 | 中 | 中 | 使用 Mock 数据开发，API 层抽象隔离 |
| 开发进度延期 | 中 | 高 | 每周五检查里程碑，必要时裁剪 MVP 范围 |
| 浏览器兼容性问题 | 低 | 中 | 第 0 周确定目标浏览器，使用 polyfill |

## ✅ 推荐执行策略

### 如果只有 1 人开发
- 执行 6 周计划，但适当延长每周时间
- 优先保证 MVP 1 和 MVP 2 的质量
- MVP 3 可裁剪部分高级功能

### 如果有 2-3 人开发
- 严格按并行开发矩阵执行
- 每日站会同步进度和阻塞问题
- 每周五进行代码审查和集成测试

### 如果时间紧迫（必须 14 天完成）
- 裁剪 MVP 范围：只保留核心模块（案件管理、证据管理、文书生成、对话 V2）
- 延迟高级功能（出庭抗辩语音、会议谈判、资深律师分析）
- 简化测试策略：仅核心流程 E2E 测试
