# 📋 法律案件追踪系统前端重设计 v3.0 — 完整计划文档
> **版本：** v3.0（模块化深度推演完整版）
> **日期：** 2026-04-02
> **状态：** 计划完成，等待实施
 

## 核心定位
**做什么：** 专业法律案件追踪辅助系统，像资深律师团队一样陪伴当事人走完案件全生命周期。
**不包含：** 项目管理（只读保留，下一步独立开发）、客户接待、时间记录等非核心功能。
**案件生命周期：**
准备 → 协商 → 诉讼 → 上诉 → 执行 → 结案
 

## 一、技术架构

### 1.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 框架 | React 18 + TypeScript 5 | 类型安全，现代化开发 |
| 构建 | Vite 5 | 极速 HMR 开发体验 |
| 路由 | React Router v6 | SPA 路由 + 嵌套路由 |
| 状态 | Zustand (全局) + TanStack Query (服务端) | 高性能状态管理 |
| 样式 | Tailwind CSS v3 + CSS 变量 | 原子化 CSS + 主题系统 |
| UI 组件 | shadcn/ui (基于 Radix primitives) | 无头组件，完全可控 |
| 图标 | Lucide React | 一致 SVG 图标 |
| 图表 | Recharts | 统计图表 |
| 图谱 | React Flow | 证据因果链可视化 |
| 表单 | React Hook Form + Zod | 高性能 + Schema 验证 |
| 导出 | @react-pdf/renderer (PDF) + docx (Word) | 多格式导出 |
| HTTP | Axios + 拦截器 | 请求封装 + 统一错误处理 |
| 通知 | Sonner | Toast 通知 |
| 动画 | Framer Motion | 页面过渡 + 微交互动效 |
| 日期 | date-fns | 轻量日期处理 |
| Diff | diff-match-patch | 草稿版本对比 |
| 持久化 | localForage | IndexedDB 封装，本地草稿存储 |
| 虚拟滚动 | @tanstack/react-virtual | 大数据量列表性能 ⭐ NEW |
| 打印 | @media print CSS + react-to-print | 法律文书打印 ⭐ NEW |
| 语音识别 | Web Speech API + @react-speech/recognition | 实时语音转文字 ⭐ NEW |
| 音频录制 | MediaRecorder API + react-mic | 会议录音存证 ⭐ NEW |
| 音频处理 | ffmpeg.wasm | 音频格式转换/压缩 ⭐ NEW |

#### 设计目标： 庭审全流程辅助，与对抗性分析深度联动。麦克风实时拾音 + 语音转文字 + 多角色发言识别 + 差异化应对策略 + 陷阱识别 + 质证意见 + 实时分析。

- 夸大事实 → 证据限定 + 可信度质疑
- 回避问题 → 重复提问 + 角度变换
- 记忆模糊 → 时间线重建 + 辅助证据

**法官提问应对：**
- 倾向性提问 → 客观陈述 + 法律依据
- 程序指令 → 配合执行 + 程序记录
- 事实确认 → 证据引用 + 准确回答
- 法律适用 → 法条引用 + 判例支持

**边界情况处理：**
- 实时分析延迟：显示"分析中..." → 提供"手动输入应对"选项 → 网络恢复后自动同步
- 声纹识别失败：显示"无法识别发言人" → 提供手动选择角色 → 继续分析
- 庭审中断：自动保存当前记录 → 恢复时可继续 → 显示"上次中断位置"
- 导入失败：显示错误提示 → 提供"手动导入"选项 → 支持逐条导入争点
- 质证记录冲突：显示冲突提示 → 提供"保留最新"或"合并"选项
- 多人同时发言：显示"多人发言，识别困难" → 建议暂停 → 提供手动分段选项

**声纹识别技术方案：**
- 预设声纹：庭前录入参会人员声纹（法官、对方律师、证人等）
- 实时识别：Web Audio API 采集音频 → 声纹特征提取 → 匹配预设声纹
- 置信度显示：显示识别置信度（>90% 高置信，70-90% 中置信，<70% 低置信）
- 降级策略：声纹识别失败 → 使用关键词识别 → 手动选择角色

#### 模块联动关系：
- 对抗性分析 → 导入争点和策略
- 证据管理 → 证据使用时机
- 质证意见 → 记录质证过程
- 陷阱检测 → 实时分析发言
- 案件画像 → 提供对方律师历史行为模式

- 导入失败：显示错误提示 + 手动导入选项
- 实时分析超时：显示"分析中..." + 超时提示
- 保存失败：显示错误提示 + 保留已填内容

**交互流程深度推演：**
1. **会议准备**：进入页面 → 选择会议类型模板 → 填写会议信息 → 关联案件 → 生成谈判要点清单
2. **会议录音**：点击"开始录音" → 请求麦克风权限 → 开始录音 → 实时语音转文字 → 显示转文字结果
3. **重点标记**：会议中点击"标记重点" → 添加时间戳标记 → 输入备注 → 自动关联到录音位置
4. **会议结束**：点击"停止录音" → 音频自动保存 → 语音转文字完成 → AI 自动生成会议纪要
5. **会后整理**：查看转文字结果 → 编辑修正识别错误 → 确认会议纪要 → 导出 PDF/发送邮件

**边界情况处理：**
- 麦克风权限被拒：显示权限请求引导 → 提供"手动输入"备选方案
- 网络断开：本地缓存录音和转文字结果 → 网络恢复后自动同步
- 语音识别率低：显示"识别率较低"提示 → 提供"手动修正"选项 → 建议安静环境录音
- 录音中断：自动保存已录制部分 → 显示"录音中断"提示 → 提供"继续录制"选项
- 音频文件过大：自动压缩音频 → 提示"文件较大，正在压缩" → 提供"分段录制"选项

**语音转文字技术方案：**
- 浏览器内置：Web Speech API（免费，支持中文，准确率 90%+）
- 云端服务：阿里云/腾讯云语音识别 API（准确率 95%+，需付费）
- 离线模式：本地缓存录音 → 网络恢复后上传转文字
- 实时模式：流式语音识别 → 逐句转文字 → 实时显示

**录音存证规范：**
- 录音格式：WAV（无损）+ MP3（压缩）双格式保存
- 元数据：时间戳、地点、参会人员、关联案件
- 完整性：录音文件哈希值校验，防止篡改
- 法律效力：符合《电子签名法》电子证据要求

## 九、工程规范与质量保障

### 10.1 代码质量规范

**ESLint 配置：**
- 使用 `@typescript-eslint/recommended` 作为基础规则
- 启用 `react-hooks/rules-of-hooks` 和 `react-hooks/exhaustive-deps`
- 自定义规则：禁止 `any` 类型、强制组件命名以大写字母开头
- 配置 `eslint-plugin-import` 确保导入顺序

**Prettier 配置：**
- 单引号、尾逗号、2 空格缩进、100 字符行宽
- 与 ESLint 集成（`eslint-config-prettier`）

**Commit 规范：**
- 采用 Conventional Commits 格式：`type(scope): description`
- 类型：`feat` | `fix` | `docs` | `style` | `refactor` | `test` | `chore`
- 使用 Husky + Commitlint 进行提交前校验

**PR 模板：**
- 变更描述、关联 Issue、测试截图、影响范围、回滚方案

### 10.2 类型安全规范

**API 响应类型：**
- 使用 `openapi-typescript` 从后端 OpenAPI Schema 自动生成 TypeScript 类型
- 所有 API 响应必须定义 Request/Response 类型
- 使用 Zod 进行运行时类型验证

**组件 Props 类型：**
- 所有组件必须定义 Props 接口
- 使用 `React.FC` 或显式返回类型
- 禁止使用 `any`，使用 `unknown` + 类型守卫

**全局类型定义：**
- `src/types/api.types.ts` — 通用 API 响应类型
- `src/types/common.types.ts` — 共享类型（分页、排序、筛选）
- 每个模块独立定义类型文件

- CSP 头配置：`script-src 'self'`

### 9.5 错误处理策略

**全局错误边界：**
- React Error Boundary 捕获组件渲染错误
- 显示友好的错误页面 + 重试按钮

**API 错误处理：**
- Axios 拦截器统一处理 HTTP 错误
- 401 → 跳转登录页
- 403 → 显示权限不足提示
- 429 → 显示限流提示 + 自动重试
- 5xx → 显示服务器错误 + 重试按钮

**网络异常处理：**
- 离线检测（navigator.onLine）
- 请求超时配置（10s）
- 自动重试（最多 3 次，指数退避）
- 降级策略：显示缓存数据

### 9.6 性能优化规范

**加载策略：**

- 组件级别懒加载（Intersection Observer）
- 图片懒加载（loading="lazy"）

**缓存策略：**
- TanStack Query 缓存：staleTime 根据数据类型配置
- 静态资源：Service Worker 缓存
- 本地草稿：localForage（IndexedDB）

**渲染优化：**

- useMemo/useCallback 避免不必要的重渲染

### 9.12 Git 分支管理规范

**分支命名规范：**
- 功能分支：`feature/模块名-功能描述`（如 `feature/evidence-upload`）
- 修复分支：`fix/模块名-问题描述`（如 `fix/timeline-calculation`）
- 优化分支：`refactor/模块名-优化描述`（如 `refactor/api-client`）
- 文档分支：`docs/文档类型-描述`（如 `docs/api-endpoints`）
- 发布分支：`release/v版本号`（如 `release/v1.0.0`）
- 热修复分支：`hotfix/问题描述`（如 `hotfix/login-crash`）

**分支管理策略：**
- `main`：生产环境代码，只能通过 release 合并
- `develop`：开发环境代码，所有功能分支合并到此
- `feature/*`：从 develop 创建，完成后合并回 develop
- `release/*`：从 develop 创建，测试完成后合并到 main 和 develop
- `hotfix/*`：从 main 创建，修复后合并到 main 和 develop

**提交规范：**
- 使用 Conventional Commits 格式
- 提交信息必须清晰描述变更内容
- 关联 Issue：`feat(evidence): add upload progress bar (#123)`
