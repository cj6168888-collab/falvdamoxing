# 法律知识图谱系统升级方案

> 基于Graphify开源项目理念，构建新一代法律知识图谱驱动系统

**文档版本**：V1.0  
**创建日期**：2026年4月8日  
**状态**：待评审

## 一、项目概述

### 1.1 背景与目标

随着法律数据量的持续增长，传统基于关键词检索和向量相似度的RAG系统已难以满足复杂法律分析的需求。本方案旨在引入知识图谱技术，将法律知识从扁平的文档集合升级为具有丰富关系网络的结构化知识体系。

**核心目标**：

| 目标 | 描述 | 预期收益 |
|------|------|----------|
| 关系驱动 | 从检索驱动转向关系驱动，显式建模法律知识之间的关联 | 支持路径查询、多跳推理 |
| 置信度体系 | 为每条法律知识标注可靠性等级 | 回答可解释、用户信任度提升 |
| 双通道提取 | 结构化提取（显式关系）与语义推断（LLM关系）分离 | Token消耗降低、提取效率提升 |
| 自动化运维 | 自动同步、自动更新、反馈回路 | 运维效率提升 |

### 1.2 设计理念

**Graphify的核心精髓**：

| 精髓 | 含义 | 法律领域映射 |
|------|------|-------------|
| **确定性提取** | 能从源码直接读出的关系，不需要LLM | 法条引用、解释适用、包含关系 |
| **语义推断** | LLM语义分析推断的关系 | 案例相似、概念关联 |
| **三级置信度** | EXTRACTED > INFERRED > AMBIGUOUS | 法律知识同样有可靠性层级 |
| **反馈回路** | 查询结果沉淀为新知识 | 用户反馈丰富图谱 |
| **可视化探索** | 交互式图谱 + 报告 | 法律知识关系可视化 |

**法律领域的独特性**：

```
代码库 vs 法律知识库
─────────────────────────────────────
Graphify:  提取调用关系、导入关系、AST结构
法律领域:  提取引用关系、适用关系、相似关系

代码库:  结构稳定，关系相对固定
法律领域:  法规更新、解释出台、案例迭代 → 图谱需持续更新

代码库:  目标单一（理解代码结构）
法律领域:  目标多元（检索、推理、证据分析、胜诉评估）
```

### 2.2 技术选型

| 组件 | 推荐方案 | 备选方案 | 选型理由 |
|------|----------|----------|----------|
| 图数据库 | **Neo4j Enterprise** | NebulaGraph, Amazon Neptune | Cypher生态最成熟，可视化最佳 |
| 向量数据库 | **Qdrant** | Milvus, Weaviate | 高性能，支持混合查询 |
| 图计算 | **NetworkX + graspologic** | Apache Giraph | Python生态集成，Leiden算法 |
| 可视化前端 | **D3.js + React** | Three.js, Cytoscape.js | 灵活可控，社区活跃 |
| 任务调度 | **Celery + Redis** | Airflow, Temporal | Python原生，成熟稳定 |
| 监控 | **Prometheus + Grafana** | DataDog | 开源生态，可定制 |

### 3.2 关系类型体系

#### 3.2.1 确定性关系 (EXTRACTED, confidence = 1.0)

```cypher
// 法条引用
(a:LegalArticle)-[:CITES {
    type: "explicit",
    confidence: 1.0,
    source: "EXTRACTED",
    context: String  // 引用上下文
}]->(b:LegalArticle)

// 解释适用
(i:LegalInterpretation)-[:APPLIES_TO {
    confidence: 1.0,
    source: "EXTRACTED",
    article_codes: [String]
}]->(a:LegalArticle)

// 案例引用法条
(c:GuidingCase)-[:CITES {
    confidence: 1.0,
    source: "EXTRACTED",
    article_codes: [String]
}]->(a:LegalArticle)

// 案件包含证据
(case:Case)-[:CONTAINS_EVIDENCE]->(e:Evidence)

// 证据支撑主张
(e:Evidence)-[:SUPPORTS]->(claim:Claim)

// 当事人提出主张
(p:Party)-[:ALLEGES]->(claim:Claim)

// 律师代理当事人
(l:Lawyer)-[:REPRESENTS]->(p:Party)
```

#### 3.2.2 推断关系 (INFERRED, confidence = 0.6-0.9)

```cypher
// 案例相似
(c1:Case)-[:SIMILAR_TO {
    confidence: Float,      // 0.6-0.9
    source: "INFERRED",
    method: "llm_analysis",
    similarity_score: Float,
    common_factors: [String]
}]->(c2:Case)

// 概念涉及
(case:Case)-[:INVOLVES]->(concept:LegalConcept)

// 术语解释
(term:LegalTerm)-[:DEFINED_AS {
    confidence: 0.9,
    source: "INFERRED",
    confidence_score: Float
}]->(concept:LegalConcept)

// 时效相关
(deadline:LegalDeadline)-[:APPLIES_TO {
    confidence: 0.85,
    source: "INFERRED"
}]->(case:Case)
```

#### 3.2.3 向量关系 (VECTOR, confidence = 0.5-0.8)

```cypher
// 语义相似（自动从向量库同步）
(n1)-[:SEMANTICALLY_SIMILAR {
    confidence: Float,
    source: "VECTOR",
    embedding_model: String,
    cosine_similarity: Float
}]->(n2)
```

#### 3.2.4 时效关系 (TEMPORAL)

```cypher
// 上位法优于下位法
(newer:LegalArticle)-[:SUPERSEDES {
    source: "EXTRACTED",
    effective_date: Date
}]->(older:LegalArticle)

// 版本继承
(v2:LegalArticle)-[:IS_VERSION_OF]->(v1:LegalArticle)
```

#### 3.2.5 推理关系 (DERIVED)

```cypher
// 因果推理
(fact1)-[:LEADS_TO {
    confidence: Float,
    source: "RULE_INFERENCE",
    rule_id: String
}]->(fact2)

// 证据链
(e1:Evidence)-[:PART_OF_CHAIN {
    sequence: Integer,
    chain_id: String
}]->(claim:Claim)
```
